### 8.0 gpt-image-2

#### 现行价格（2026-05-12 起，`v2026.11.07` 仍用这张表）

**输入图片（参考图）：固定 0.100 元/张，与 quality 和 size 无关，按实际传入张数计费，不随** `n` **翻倍。**

| quality | 1K（元/张） | 2K（元/张） | 4K（元/张） |
|---------|-----------|-----------|-----------|
| low | 0.045 | 0.090 | 0.150 |
| medium | 0.398 | 0.803 | 1.335 |
| high | 1.583 | 3.210 | 5.340 |

> **计费结构**：总费用 = 生成成本（quality × size × n） + 输入图片成本（0.100 元 × 张数）  
> 输入图片成本**不受 quality、size、n 影响**，只看传了几张参考图。

#### 计费表达式

有 `size` 时按总像素分档。没有 `size` 时按 `resolution` 分档，缺省 `1K`。`low`、`xhigh`、`max` 和未传同一档，`medium`、`high` 各一档。`hd`、`standard` 不再识别。

| 档位 | 判定 |
|------|------|
| 1K | 有 size 且总像素 ≤ 1024×1024，或 resolution 不是 2K/4K，或两个字段都没传 |
| 2K | 1024×1024 < 总像素 ≤ 2048×2048，或 `resolution` 为 `2K` |
| 4K | 总像素 > 2048×2048，或 `resolution` 为 `4K` |

```
let q = param("quality");
let sz = param("size");
let res = param("resolution");
let px = (sz != nil && sz != "") ? pixels(sz) : 0;
let n = param("n") != nil ? param("n") : 1;
let imgCount = param("image") == nil ? 0 : (param("image.#") != nil && param("image.#") > 0 ? param("image.#") : 1);
let band = px > 2048 * 2048 ? "4K" : px > 1024 * 1024 ? "2K" : px > 0 ? "1K" : ((res == "4K" || res == "4k") ? "4K" : ((res == "2K" || res == "2k") ? "2K" : "1K"));
(
  q == "high" ? (
    band == "4K" ? tier("high-4K", 731507) :
    band == "2K" ? tier("high-2K", 439726) :
    tier("high-1K", 216849)
  ) : q == "medium" ? (
    band == "4K" ? tier("medium-4K", 182877) :
    band == "2K" ? tier("medium-2K", 109973) :
    tier("medium-1K", 54521)
  ) : (
    band == "4K" ? tier("low-4K", 20548) :
    band == "2K" ? tier("low-2K", 12329) :
    tier("low-1K", 6164)
  )
) * n + imgCount * 13699
```

> **输入图片计数逻辑**：  
> `param("image.#")` 用 gjson `#` 获取数组长度；`image` 为字符串（单张）时 `#` 不存在，按 1 张计；未传 `image` 时不收输入图费用。  
> **注意**：旧表达式把 `1024x1792` 标成 4K，实际约 1.8M 像素，现按总像素归入 2K。自定义大图（如 `2880x2880`）会进入 4K，不再掉进 1K 兜底。

### 8.5 Qwen 系列

#### qwen-image-0925

Qwen 使用 `size` 传像素尺寸（如 `1024x1024`），无标准 quality 档位。合法总像素范围 `[512×512, 2048×2048]`，最大 ~4.2M 像素。

> **注意**：Qwen 合法 size 的边长不超过 2048，因此永远不会出现含 `4096` 的 size，4K 档在实际使用中命中不到。建议运营确认是否需要保留 4K 档位，或简化为只有 1K/2K 分档。

用 `pixels()` 按总像素分档（比 `has()` 准确，不会误判如 `2048x512` 这类极端比例）：

```
pixels(param("size")) > 1024 * 1024 ? tier("2K", 52055) :
tier("1K", 41096)
```

> 如确实需要 4K 档，或所有用户均使用相同尺寸，也可直接配置固定价（如 `tier("1K", 41096)`）。

### 8.6 Hunyuan 系列

#### hunyuan-image-3.0

Hunyuan 使用 `size` 传像素尺寸，无标准 quality 档位。合法约束：宽高各维度 `[512, 2048]`，**宽×高乘积 ≤ 1024×1024**（约 1M 像素）。

> **注意**：Hunyuan 的像素乘积上限恰好是 1M（= 1K 档上界），2K 和 4K 档在实际使用中永远命中不到。建议配置固定价：

tier("1K", 27397)
```

> 若运营未来扩大了 Hunyuan 像素上限，可改用 `pixels()` 分档：
>
> ```
> has(param("size"), "4096") ? tier("4K", 49315) :
> has(param("size"), "2048") ? tier("2K", 38356) :
> tier("1K", 27397)
> ```

### 8.8 APIMart gpt-image-2.5 / 2.6

下面只适用于 `gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`、`gpt-image-2.6-flare`、`gpt-image-2.6-sunburst`。计费方式选阶梯表达式。系数是平台自己的 `$/1M tokens`，完成时用上游返回的 token 再算一次，多退少补。

APIMart 标价单位是 Credits，1 美元 = 10 Credits，并且按 1 美元 = 7 元计人民币。平台按 1 美元 = 7.3 元入账。换成平台系数：

```
平台 $/1M tokens = APIMart Credits / 1M tokens ÷ 10 × 7 ÷ 7.3
```

只除以 10 会按 7.3 元把同一笔成本记高。这是上游成本。售价在表达式里另填，可以高于成本。

| 类别 | 表达式变量 | APIMart 成本 | APIMart $/1M | 平台 $/1M |
|---|---|---:|---:|---:|
| 文本输入 | `p` | 40 Credits / 1M | 4 | 3.835616 |
| 缓存文本输入 | `cr` | 10 Credits / 1M | 1 | 0.958904 |
| 图片输入 | `img` | 64 Credits / 1M | 6.4 | 6.136986 |
| 缓存图片输入 | `cc` | 16 Credits / 1M | 1.6 | 1.534247 |
| 图片输出 | `img_o` | 240 Credits / 1M | 24 | 23.013699 |

提交时还没有 token，表达式要先冻一笔预扣。有 token 后再按系数结算。表达式先按 Credits ÷ 10 得到 APIMart 美元，再乘 7 除以 7.3。上线前可以把系数改成平台售价。

```
(p + cr + img + cc + img_o) > 0
  ? tier("actual", (p * 4 + cr * 1 + img * 6.4 + cc * 1.6 + img_o * 24) * 7 / 7.3)
  : tier("precharge", 1000000)
```

`tier("precharge", 1000000)` 先冻 $1。不要配按次固定价，按次没有这套 token 系数。

APIMart 渠道里按张计费的其他图片模型不要套这个表达式，各自配按张价格。

实测 `gpt-image-2.6-flare`：文本 274、图片输入 1508、图片输出 1449。按成本系数结算额度 21826，约 $0.04365，约 0.319 元。APIMart 美元约 $0.04552，乘 7 也是 0.319 元。售价系数改大后，额度按新系数涨。

### 8.11 APIMart MAI / Qwen Image 3.0 / Muse / Hunyuan

换算和 FLUX 相同：Credits ÷ 10 得到美元，美元乘 7 得到人民币，再 `round(人民币 ÷ 7.3 × 1,000,000)`。计费方式选阶梯表达式。模型加到已有 APIMart Image 渠道，公开名和上游名相同。
