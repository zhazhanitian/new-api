# 图片四字段发布与回滚

网关、后台计费表达式、下游产品必须同一时间窗口上线。

只上网关时，下游旧字段会收到 400。只上下游时，网关会忽略新字段，表达式按缺省档计费。

## 发布前

1. 备份后台里这 20 个模型的计费表达式：原有 16 个图片模型，加上 `gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`、`gpt-image-2.6-flare`、`gpt-image-2.6-sunburst`。
2. 按 [图像生成模型价格配置](图像生成模型价格配置.md) 文首当前版本改表达式。本次对应 `v2026.11.07`。Gemini、Kling、Vidu 改读 `resolution`。gpt-image-2 在没有 `size` 时改读 `resolution`。APIMart 的 `gpt-image-2.5` / `2.6` 四个模型配阶梯表达式，系数用平台 `$/1M tokens`。APIMart Credits 先除以 10 得到成本，售价在表达式里另填。同一渠道里按张计费的其他图片模型各自配价格。
3. Seedream、Qwen、Hunyuan 按 [图像生成模型价格配置](图像生成模型价格配置.md) 8.7 填写。Seedream、Hunyuan 已是固定单价的不用改。Qwen 继续读 `pixels(param("size"))`。
4. 新增渠道类型 APIMart Image，默认地址 `https://apib.ai`。如果生图端点只在 `https://api.apimart.ai` 可用，在渠道里改 Base URL。
5. 用新字段对每个模型做一次预扣。确认没有落到缺省档。
6. 如果某个已登记模型还配在会原样透传请求体的渠道上，`resolution` 和 `ratio` 不会被转换成该渠道的字段。发布前查一下渠道上的模型配置。

## 回滚

三者一起退回：网关版本、后台表达式备份、下游调用。不要只退其中一个。

已经提交的任务继续用旧的任务数据轮询，不需要迁移。
