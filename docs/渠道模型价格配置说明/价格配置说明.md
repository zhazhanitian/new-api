# New API 价格配置说明

> 本文档记录平台价格配置相关的常见问题与配置方法，供运营/配置人员参考。

---

## 一、计费方式概览

平台支持三种计费方式，在模型倍率设置页面切换：

| 计费方式 | 适用场景 | 说明 |
|---------|---------|------|
| **按量计费** | 普通对话模型 | 直接填输入/输出价格（$/M tokens），最常用 |
| **按次计费** | 固定收费的模型 | 每次调用收固定费用，适合按图片张数收费等场景 |
| **表达式/阶梯计费** | 价格与请求参数挂钩 | 支持根据 token 数、请求参数、时间等动态计算价格 |

---

## 二、内部积分（Quota）换算

平台内部使用积分（quota）体系，不直接用美元扣费。

**默认换算关系：$1 = 500,000 quota**

在填写表达式时，表达式返回值与实际费用的换算：

```
实际费用 = 表达式返回值 / 1,000,000 × 500,000
         = 表达式返回值 × 0.5 (quota 单位)
         = 表达式返回值 / 1,000,000 (美元)
```

对于普通对话模型，表达式系数就是 $/M tokens，填起来很直观（如 `p * 3` 表示 $3/M 输入 token）。

---

## 三、表达式计费变量说明

| 变量 | 含义 | 说明 |
|-----|------|------|
| `p` | 输入 token 数（文本） | 自动排除已单独计费的子类（图片/音频/缓存） |
| `c` | 输出 token 数（文本） | 自动排除已单独计费的子类 |
| `len` | 输入上下文总长度 | 仅用于阶梯条件判断，不参与价格计算 |
| `cr` | 缓存读取 token 数 | 命中缓存时的读取量 |
| `cc` | 缓存创建 token 数（5分钟） | 首次创建缓存时 |
| `cc1h` | 缓存创建 token 数（1小时） | Claude 专属长效缓存 |
| `img` | 图片输入 token 数 | 发给模型的图片（视觉理解） |
| `img_o` | 图片输出 token 数 | 模型生成的图片 |
| `ai` | 音频输入 token 数 | |
| `ao` | 音频输出 token 数 | |

> **注意**：只有在表达式中使用了某个变量，系统才会将其从 `p`/`c` 中剔除单独计算，避免重复收费。

## 四、各场景配置示例

### 4.1 普通对话模型（按量计费）

直接在「按量计费」标签填写即可，无需写表达式。

**示例：Claude Sonnet 4.5**
- 输入价格：`3` （$3/M tokens）
- 输出价格：`15` （$15/M tokens）
- 缓存读取价格：`0.3`
- 缓存创建价格：`3.75`

---

### 4.2 带音频的多模态模型（表达式计费）

适用于：Gemini 系列（音频与文本输入价格不同）

**示例：gemini-3.1-flash-lite-preview**

| 字段 | 值 | 说明 |
|------|----|------|
| 输入价格 | `0.25` | 文本+图片+视频统一 $0.25/M |
| 输出价格 | `1.5` | $1.5/M |
| 缓存读取价格 | `0.03` | $0.03/M |
| 图片输入价格 | `0` | 与文本同价，留在 p 里一起算 |
| 音频输入价格 | `0.5` | $0.5/M，系统自动从 p 中剔出单独计费 |

等价表达式：`tier("base", p * 0.25 + cr * 0.03 + ai * 0.5 + c * 1.5)`

> 图片与文本输入价格相同时，图片输入价格填 0 即可，图片 token 会自动归入 `p` 按文本价格计算。

---

### 4.3 图像生成模型（按 token 计费）

适用于：gpt-image-2、gpt-image-1 等

这类模型的 usage 结构通常为：
- 输入：文本 token（`p`）
- 输出：图片 token（`img_o`）

**配置：**

| 字段 | 值 |
|------|----|
| 输入价格 | `5` |
| 输出价格 | `10` |
| 图片输入价格 | `8`（如有图生图场景） |
| 图片输出价格 | `32` |

等价表达式：`tier("base", p * 5 + img * 8 + c * 10 + img_o * 32)`

---

### 4.4 图像生成模型（按分辨率/张数计费）

适用于：按图片尺寸收费的模型

**表达式（含多张图支持）：**

```
(param("size") == "4096x4096" ? tier("4K", 18000) : param("size") == "2048x2048" ? tier("2K", 12000) : tier("1K", 6000)) * (param("n") != nil ? param("n") : 1)
```

价格对应关系（基于默认汇率 $1 = 500,000 quota）：

| 档位 | 表达式值 | 对应价格 |
|-----|---------|---------|
| 1K 图 | 6,000 | $0.006/张 |
| 2K 图 | 12,000 | $0.012/张 |
| 4K 图 | 18,000 | $0.018/张 |

> `param("size")` 读取请求 body 中的 `size` 字段，`param("n")` 读取图片数量。
> Token 估算器会提示 "param is not defined"，这是预览工具的限制，不影响实际计费，直接保存即可。

---

### 4.5 图像生成模型（固定单价/张，不按分辨率分档）

适用于：所有分辨率统一定价的模型，如 `doubao-seedream-4-5-251128`（文生图、图生图均为同一价格）

#### 表达式值计算公式

系统内部以美元计费，表达式值与美元价格的换算关系为：

```
表达式值 = 每张价格（美元） × 1,000,000
```

> 之所以乘以 1,000,000，是因为系统在结算时会将表达式值除以 1,000,000 还原为美元价格。这个设计与 token 计费保持一致（$/M tokens）。

如果你知道的是**人民币**单价，需要先按汇率换算：

```
每张价格（美元） = 每张价格（元） ÷ 汇率

表达式值 = 每张价格（元） ÷ 汇率 × 1,000,000
```

**示例：豆包 Seedream-4.5，0.25 元/张，平台固定汇率 1 USD = 7.3 CNY**

```
表达式值 = 0.25 ÷ 7.3 × 1,000,000 ≈ 34,247
```

> **注意**：平台固定汇率为 **7.3 CNY/USD**，所有模型的表达式值均按此汇率计算，无需动态调整。

**配置表达式（支持多张图）：**

```
tier("fixed", 34247) * (param("n") != nil ? param("n") : 1)
```

- `tier("fixed", 34247)`：每张图固定扣除对应 quota（0.25 元 ÷ 7.3 × 1,000,000 ≈ 34,247）
- `* (param("n") != nil ? param("n") : 1)`：请求几张图就乘以几，未传 `n` 时默认按 1 张算

**验算（固定汇率 7.3）：**

> 注：示例表达式值 34,247 基于固定汇率 7.3，原示例 36,800 已过期。

```
quota 扣除量 = 34,247 × 0.5 = 17,124 quota
美元价格    = 17,124 ÷ 500,000 = $0.03425/张
人民币价格  = $0.03425 × 7.3 ≈ 0.25 元/张 ✓
```

## 五、缓存价格说明（Claude 专属）

Claude 系列模型支持 **Prompt Caching** 功能，分为两种计费：

| 计费项 | 触发时机 | 特点 |
|------|---------|------|
| **缓存创建价格** | 客户端发送带 `cache_control` 标记的请求，首次写入缓存时 | 略贵于普通输入（约 1.25x），需要存储成本 |
| **缓存读取价格** | 后续请求命中已缓存内容时 | 远低于普通输入（约 10%），多次复用越省钱 |

**触发条件**：客户端必须在请求中显式加 `cache_control` 标记才会触发，普通调用不产生缓存费用。

**示例场景**：长系统提示词（如知识库、角色设定）在多轮对话中保持不变时，使用缓存可大幅降低成本。

## 六、模型广场端点配置

在模型管理的「展示端点」字段，可控制模型广场中显示的 API 接口地址（仅影响展示，不影响实际路由）。

| 端点类型 Key | 对应接口 | 适用模型 |
|------------|---------|---------|
| `openai` | `/v1/chat/completions` | 普通对话模型（默认） |
| `openai-response` | `/v1/responses` | gpt-5.4-pro、gpt-5.3-codex 等 |
| `image-generation` | `/v1/images/generations` | 图像生成模型（同步） |
| `image-task` | `/v2/image-tasks` | 图像生成模型（异步任务） |
| `openai-video` | `/v1/video/generations` | 视频生成模型（豆包 Seedance、可灵等） |
| `embeddings` | `/v1/embeddings` | 向量模型 |

**填写格式（JSON）：**

```json
{"image-generation": {"path": "/v1/images/generations", "method": "POST"}}
```

同时展示同步和异步接口（在同一 JSON 对象中写多个 key）：

```json
{
  "image-generation": {"path": "/v1/images/generations", "method": "POST"},
  "image-task": {"path": "/v2/image-tasks", "method": "POST"}
}
```

> 填写后替换默认端点（不合并），若需同时展示多个端点，在同一 JSON 对象中写多个 key。

## 七、表达式计费与异步任务接口

**异步任务接口**（`POST /v2/image-tasks`）支持表达式/阶梯计费。  
> v1 异步接口（`/v1/image-tasks/submit`）已停止维护，新模型请统一使用 v2 接口。

表达式在请求进入时即计算价格并预扣费，`param("quality")`、`param("size")`、`param("n")` 等函数从请求 body 中实时读取参数值。

配置示例（gpt-image-2 按质量和总像素分档），详细说明见 [图像生成模型价格配置.md](./图像生成模型价格配置.md) 8.0 节。

```
let q = param("quality");
let px = pixels(param("size"));
let n = param("n") != nil ? param("n") : 1;
let imgCount = param("image") == nil ? 0 : (param("image.#") != nil && param("image.#") > 0 ? param("image.#") : 1);
(
  (q == "high" || q == "hd") ? (
    px > 2048 * 2048 ? tier("high-4K", 731507) :
    px > 1024 * 1024 ? tier("high-2K", 439726) :
    tier("high-1K", 216849)
  ) : q == "medium" ? (
    px > 2048 * 2048 ? tier("medium-4K", 182877) :
    px > 1024 * 1024 ? tier("medium-2K", 109973) :
    tier("medium-1K", 54521)
  ) : (
    px > 2048 * 2048 ? tier("low-4K", 20548) :
    px > 1024 * 1024 ? tier("low-2K", 12329) :
    tier("low-1K", 6164)
  )
) * n + imgCount * 13699
```

> **注意**：Token 估算器会提示 "param is not defined"，这是预览工具的限制，不影响实际计费，直接保存即可。

### 9.1 Seedance 2.0 / 2.0-fast / 2.0-mini（含/不含视频输入）

#### 官方原价（元 / 百万 Token，480P/720P 基准）

| 模型 | 包含视频输入 | 不含视频输入 |
|------|-------------|-------------|
| Seedance 2.0 | 28 | 46 |
| Seedance 2.0-fast | 22 | 37 |
| Seedance 2.0-mini | 14 | 23 |

> 以上型号 **没有**有声/无声差价。

#### 配置规则（只填「不含视频」基准价）

后台 **只配置「不含视频输入」那一档较高费率**。系统在请求时自动乘以下折扣：

| 自动调价项 | 触发条件 | 2.0 | 2.0-fast | 2.0-mini |
|-----------|---------|-----|----------|----------|
| 视频输入折扣 | metadata 中含视频输入 | `28/46 ≈ 0.6087` | `22/37 ≈ 0.5946` | `14/23 ≈ 0.6087` |
| 1080P 溢价 | 分辨率为 1080p | `31/28 ≈ 1.1071` | 不适用 | 不适用 |
| 4K 折扣 | 分辨率为 4K | `26/46 ≈ 0.5652` | 不适用 | 不适用 |

> fast / mini 仅支持 480P/720P，无需配置分辨率系数。

因此：

- **480P / 720P、无视频输入** → 直接按填写的输入价格计费  
- **有视频输入** → 自动打折到「含视频」档  
- **仅 2.0 的 1080P / 4K** → 再叠分辨率系数  

#### 输入价格（经销 ×1.05）

```
输入价格（$/1M tokens） = 官方「不含视频」单价（元） × 1.05 ÷ 7.3
```

| 模型 | 官方不含视频（元） | 经销价（×1.05，元） | **输入价格应填** | 摘要显示（≈） |
|------|-------------------|-------------------|-----------------|--------------|
| `doubao-seedance-2-0-260128` | 46 | 48.30 | **6.6164** | ¥48.30 / 1M tokens |
| `doubao-seedance-2-0-fast-260128` | 37 | 38.85 | **5.3219** | ¥38.85 / 1M tokens |
| `doubao-seedance-2-0-mini-260615` | 23 | 24.15 | **3.3082** | ¥24.15 / 1M tokens |
| `dreamina-seedance-2-0-260128` | 同 2.0 | 同左 | **6.6164** | 同左 |
| `dreamina-seedance-2-0-fast-260128` | 同 2.0-fast | 同左 | **5.3219** | 同左 |

**验算：**

```
2.0 输入价格     = 46 × 1.05 ÷ 7.3 = 48.30 ÷ 7.3 ≈ 6.6164
2.0-fast 输入价格 = 37 × 1.05 ÷ 7.3 = 38.85 ÷ 7.3 ≈ 5.3219
2.0-mini 输入价格 = 23 × 1.05 ÷ 7.3 = 24.15 ÷ 7.3 ≈ 3.3082

mini 有视频输入时 ≈ 24.15 × (14/23) = 14.70 元/百万 Token（即官方含视频 14 × 1.05）
```

### 9.2 Seedance 1.5-pro（有声 / 无声）

#### 官方原价（元 / 百万 Token）

1.5-pro 按 **有声 / 无声** 分档（不是「是否含视频输入」）。当前按 **官方原价** 配置（不加经销倍率）：

| 计费项 | 官方原价（元） |
|--------|---------------|
| 有声 | **16** |
| 无声 | **8** |
| 批量推理有声 | 8 |
| 批量推理无声 | 4 |

> 平台代码目前只自动区分「有声 / 无声」，**未单独实现「批量推理」档位**。批量推理价仅作官方价目参考。

#### 配置规则（只填「有声」基准价）

| 自动调价项 | 触发条件 | 比率 |
|-----------|---------|------|
| 无声视频折扣 | 未开启音频（无声） | `8/16 = 0.5` |

- **有声** → 直接按填写的输入价格计费  
- **无声** → 自动 × 0.5，落到无声档  

#### 输入价格（官方原价 ×1）

```
输入价格（$/1M tokens） = 官方有声单价（元） ÷ 7.3
```

| 模型 | 官方有声（元） | **输入价格应填** | 摘要显示（≈） |
|------|---------------|-----------------|--------------|
| `doubao-seedance-1-5-pro-251215` | 16 | **2.1918** | ¥16.00 / 1M tokens |

**验算：**

```
输入价格 = 16 ÷ 7.3 ≈ 2.1918
摘要人民币 = 2.1918 × 7.3 ≈ 16.00 元/百万 Token ✓
无声时实际单价 ≈ 16 × 0.5 = 8.00 元/百万 Token
```

### 9.3 后台配置步骤

1. 打开对应模型的「计费方式」→ 选择 **按量计费**  
2. **输入价格**按上表填写

4. 保存后核对「价格摘要」人民币是否与上表「摘要显示」一致

### 9.5 历史配置说明（供对照）

早期若按 **官方 × 1.5、汇率 7.5** 配置 2.0，会出现：

```
46 × 1.5 ÷ 7.5 = 9.2
```

即输入价格填 `9.2`。在平台汇率改为 **7.3** 后，摘要会显示为 `9.2 × 7.3 ≈ ¥67.16`，与「官方 × 1.5 = ¥69」略有偏差。  
改用经销价（×1.05）时，请统一按 **§9.1** 用汇率 **7.3** 重算，不要在旧的 `9.2` 上直接乘 `1.05/1.5`。
