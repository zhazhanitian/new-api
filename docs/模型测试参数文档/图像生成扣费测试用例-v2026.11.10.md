# 图像生成扣费测试用例

对照 [图像生成模型价格配置](../渠道模型价格配置说明/图像生成模型价格配置.md) `v2026.11.10.2` 的 8.10、8.11。用来确认本期新增模型的阶梯表达式扣得对不对。

| 项 | 内容 |
|---|---|
| 文档版本 | `v2026.11.10` |
| 修订日期 | 2026-11-10 |
| 价格文档 | `图像生成模型价格配置.md` `v2026.11.10.2` |
| 接口 | `POST /v2/image-tasks`，再用 `GET /v2/image-tasks/{task_id}` 看 `data.amount` |
| 分组倍率 | 下表按 **1**。key 的分组倍率不是 1 时，预期金额再乘倍率 |
| 汇率 | `data.amount` 是人民币，6 位小数，按 `1 USD = 7.3 CNY` 从额度换算 |

`BASE_URL`、`YOUR_API_KEY` 换成实际值。`image` 里的地址换成可访问的图。任务失败会退款，**用成功任务的 `data.amount` 对账**。

这批模型按张预扣，成功后不按 token 重算。`SUCCESS` 时的金额应和提交时一样。

换算：

```
额度 = 四舍五入(表达式值 / 1,000,000 × 500,000 × 分组倍率)
amount = 额度 / 500,000 × 7.3
```

预期 `amount` 已经按额度四舍五入算过。它和标价差在 0.00001 元以内，是表达式取整造成的，不是少扣。差到分，就是表达式没配对。

`resolution` 是档位，`ratio` 是宽高比，`size` 只写宽x高。这些模型不要传 `quality`。

  -H "Content-Type: application/json" \

    "prompt": "一只在窗台上的橘猫",
    "size": "1024x1024",
    "n": 1,
    "extra_fields": {
      "width": 1536,
      "height": 1536
