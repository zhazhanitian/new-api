# 图像生成扣费测试用例

对照 [图像生成模型价格配置](../渠道模型价格配置说明/图像生成模型价格配置.md) `v2026.11.07`。用来确认后台表达式扣得对不对。

| 项 | 内容 |
|---|---|
| 文档版本 | `v2026.11.07` |
| 修订日期 | 2026-11-07 |
| 价格文档 | `图像生成模型价格配置.md` `v2026.11.07` |
| 接口 | `POST /v2/image-tasks`，再用 `GET /v2/image-tasks/{task_id}` 看 `data.amount` |
| 分组倍率 | 下表按 **1**。key 的分组倍率不是 1 时，预期金额再乘倍率 |
| 汇率 | `data.amount` 是人民币，6 位小数，按 `1 USD = 7.3 CNY` 从额度换算 |

`BASE_URL`、`YOUR_API_KEY` 换成实际值。`image` 里的地址换成可访问的图。任务失败会退款，**用成功任务的 `data.amount` 对账**。

旧写法 `size=16:9`、`quality=1K`、`quality=2K` 会返回 400，扣不到费。本文件的 `resolution` 是档位，`ratio` 是宽高比，`size` 只写宽x高，`quality` 只写 `low` / `medium` / `high`。

预期 `amount` 已经按额度四舍五入算过。它和标价差在 0.00001 元以内，是表达式取整造成的，不是少扣。差到分，就是表达式没配对。

5.0 pro、5.0 flash、Seedream 3.0 报价单没有单价，这一版不列用例。

## APIMart gpt-image-2.5 / 2.6

只这四个模型：`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`、`gpt-image-2.6-flare`、`gpt-image-2.6-sunburst`。

后台表达式按价格文档 8.8 配置时：

- 生成中，四个模型的 `data.amount` 都是 **`7.300000`**（预扣 1 美元）。
- 成功后按这次返回的 token 重算，`amount` 会变。公开查询只有 `usage.input_tokens`、`usage.output_tokens`、`usage.total_tokens`，对不上文本、图片、缓存的拆分。拆分看后台这次任务的用量明细。

成本系数（上线前如果改成售价，用后台里的系数，不要用这组数）：

```
amount 对应的表达式值 = p * 4 + cr * 1 + img * 6.4 + cc * 1.6 + img_o * 24
额度 = 四舍五入(表达式值 / 1,000,000 × 500,000 × 分组倍率)
amount = 额度 / 500,000 × 7.3
```

| 变量 | 用量 |
|---|---|
| `p` | 未缓存文本输入 |
| `cr` | 缓存文本输入 |
| `img` | 未缓存图片输入 |
| `cc` | 缓存图片输入 |
| `img_o` | 图片输出 |

价格文档里的一笔实测：文本 274、图片输入 1508、图片输出 1449，缓存为 0。成本系数下额度 22762，`amount` 为 `0.332325`。那是那一次调用的用量，这次调用对不上这个数是正常的。

四个模型各跑一条。生成中都应是 `7.300000`，成功后再用上面的公式对最终 `amount`。
