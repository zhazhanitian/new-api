## 1. 快速开始

### 1.1 Base URL

| 环境 | Base URL |
|---|---|
| 本地 | `http://localhost:38417` |
| 生产 | 由支付中心提供的 HTTPS 域名 |

业务接口前缀：`/api/pay`。不要调用 `/api/pay/callback/*`（微信渠道回调，不是给业务系统的）。

对接前向支付中心索取：`apiKey`（调接口）、`notifyKey`（验回调）。产品须已配置公网可达的 `callbackUrl`，否则支付/退款成功后无法通知你们。

### 1.2 通用请求头

```http
Authorization: Bearer <apiKey>
Content-Type: application/json
```

产品请求**不需要**额外签名。GET 可不带 `Content-Type`。

限流（超限为 **HTTP 429**，不是 HTTP 200）：

| 接口 | 限制 |
|---|---|
| `POST /api/pay/orders` | 每个 API Key 每分钟 60 次 |
| `POST /api/pay/refunds` | 每个 API Key 每分钟 30 次 |

### 1.3 通用响应包

**HTTP 200 不等于业务成功。** 除限流外，接口一律 HTTP 200，用 body 的 `code` / `success` 判断。

成功：

```json
{
  "code": 200,
  "success": true,
  "message": "订单创建成功",
  "data": {}
}
```

失败（HTTP 仍为 200）：

```json
{
  "code": 400,
  "success": false,
  "message": "业务订单已支付成功，请勿重复下单",
  "data": {}
}
```

限流（HTTP **429**，无 `success` 字段）：

```json
{
  "code": 429,
  "message": "请求过于频繁，请稍后再试",
  "data": null
}
```

判定规则：`code === 200 && success === true` 才是业务成功。

金额单位：**分**，JSON **整数**。1 元传 `100`。货币固定 `CNY`，请求体不传。

订单号：支付中心生成 `PAY{YYYYMMDD}{9位序列}`，如 `PAY20260911000000001`。退款单号 `REF{YYYYMMDD}{9位序列}`。

## 2. 鉴权

所有 `/api/pay/orders`、`/api/pay/refunds` 接口走 `Authorization: Bearer <apiKey>`。`apiKey` 为产品 64 位 hex。

```http
GET /api/pay/orders/PAY20260911000000001 HTTP/1.1
Host: localhost:38417
Authorization: Bearer 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
```

```bash
curl -sS 'http://localhost:38417/api/pay/orders/PAY20260911000000001' \
  -H 'Authorization: Bearer <apiKey>'
```

| 情况 | HTTP | code | message |
|---|---|---|---|
| 缺少 `Authorization` 或非 `Bearer ` 前缀 | 200 | 401 | `缺少 Authorization 头` |
| apiKey 不存在 | 200 | 401 | `API Key 无效` |
| 产品已禁用 | 200 | 403 | `产品已禁用` |
| 其它鉴权异常 | 200 | 401 | `鉴权失败` |

Key 只能操作本产品订单/退款。查不到其它产品的单。

## 4. 创建支付订单 `POST /api/pay/orders`

### 请求参数（JSON body）

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| businessOrderNo | string | 是 | ≤128 | 你们的业务单号，同一产品内唯一，用作幂等键 |
| amount | number | 是 | 整数，≥1 | 支付金额，**分** |
| subject | string | 是 | ≤256 | 订单标题（微信商品描述） |
| body | string | 否 | ≤512 | 订单描述 |
| channel | string | 是 | 仅 `WECHAT` | 支付渠道 |
| payType | string | 是 | `JSAPI` / `H5` / `NATIVE` | 支付方式（不要传 `APP`） |
| payerOpenId | string | JSAPI 必填 | ≤128 | 付款人 openid，必须与下单所用 APPID 同源 |
| clientIp | string | H5 必填 | ≤64 | 用户真实公网 IP |
| attach | string | 否 | ≤512 | 附加数据，支付成功通知原样回传 |
| expireMinutes | number | 否 | ≥1，默认 30 | 订单过期分钟数 |

幂等（同一产品 + `businessOrderNo`）：

- 无记录：创建并调微信，成功后 `status` 一般为 `PAYING`
- `CREATED` / `PAYING`：重新调起，返回**原订单** + 新 `payParams`
- `SUCCESS`：`code=400`，`业务订单已支付成功，请勿重复下单`
- `CLOSED`：`code=400`，`订单已关闭，请重新下单`（换新 `businessOrderNo`）

未配置渠道映射：`code=400`，`该产品未配置此支付渠道`。

### 请求示例

JSAPI：

```json
{
  "businessOrderNo": "BIZ20260911001",
  "amount": 100,
  "subject": "会员充值",
  "channel": "WECHAT",
  "payType": "JSAPI",
  "payerOpenId": "oXXXX",
  "attach": "userId=10001",
  "expireMinutes": 30
}
```

H5：

```json
{
  "businessOrderNo": "BIZ20260911002",
  "amount": 100,
  "subject": "会员充值",
  "channel": "WECHAT",
  "payType": "H5",
  "clientIp": "114.221.90.24"
}
```

NATIVE：

```json
{
  "businessOrderNo": "BIZ20260911003",
  "amount": 100,
  "subject": "会员充值",
  "channel": "WECHAT",
  "payType": "NATIVE"
}
```

### 成功响应

```json
{
  "code": 200,
  "success": true,
  "message": "订单创建成功",
  "data": {
    "orderNo": "PAY20260911000000001",
    "status": "PAYING",
    "amount": 100,
    "payParams": {}
  }
}
```

`payParams` 随 `payType` 变化：

**JSAPI** — 给微信内调起支付（`wx.requestPayment` / `getBrandWCPayRequest`）：

```json
{
  "appId": "wxabcdef1234567890",
  "timeStamp": "1726032000",
  "nonceStr": "a1b2c3d4e5f67890a1b2c3d4e5f67890",
  "package": "prepay_id=wx2014102720093957147447be07654321",
  "signType": "RSA",
  "paySign": "Base64Signature=="
}
```

**H5** — 引导用户打开该 URL：

```json
{ "h5Url": "https://wx.tenpay.com/cgi-bin/mmpayweb-bin/checkmweb?prepay_id=..." }
```

**NATIVE** — 将该字符串生成二维码：

```json
{ "codeUrl": "weixin://wxpay/bizpayurl?pr=xxxxx" }
```

### 失败响应

```json
{
  "code": 400,
  "success": false,
  "message": "JSAPI 支付需要 openid",
  "data": {}
}
```

参数校验失败同样 `code=400`，`message` 为 class-validator 拼出的中文，例如 `业务订单号不能为空`、`支付金额最少 1 分`。

## 5. 查询订单（支付中心单号） `GET /api/pay/orders/{orderNo}`

查**本地库**，不实时查微信。

### 路径参数

| 字段 | 位置 | 说明 |
|---|---|---|
| orderNo | path | 支付中心订单号，`PAY` 开头 |

### 成功响应

```json
{
  "code": 200,
  "success": true,
  "message": "",
  "data": {
    "orderNo": "PAY20260911000000001",
    "businessOrderNo": "BIZ20260911001",
    "amount": 100,
    "status": "SUCCESS",
    "paidAt": "2026-09-11T03:12:00.000Z",

```

| 字段 | 类型 | 说明 |
|---|---|---|

| businessOrderNo | string | 业务订单号 |

## 7. 关闭订单 `POST /api/pay/orders/{orderNo}/close`

无 body。仅 `CREATED`、`PAYING` 可关。会调微信关单并把本地状态改为 `CLOSED`。

其它状态：`code=400`，`当前订单状态 [${status}] 不可关闭`。

### 成功响应

```json
{
  "code": 200,
  "success": true,
  "message": "订单已关闭",
  "data": {}
}
```

## 8. 申请退款 `POST /api/pay/refunds`

### 请求参数

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| orderNo | string | 是 | 支付中心单号 `PAY...` | 不是业务单号 |
| refundAmount | number | 是 | 整数，≥1 | 本次退款金额，**分** |
| reason | string | 是 | ≤256 | 退款原因 |
| businessRefundNo | string | 否 | ≤128 | 业务退款单号，同一支付单 + 此号幂等 |

允许退款的订单状态：`SUCCESS`、`REFUNDING`。已全额退：`订单已全额退款`。其它状态：`当前订单状态（${status}）不允许退款`。

可多次部分退款。占用额 = 状态不是 `FAILED`/`CLOSED` 的退款单金额之和；超出：`退款金额超出可退范围，已占用 X 分，最多可再退 Y 分`。

**本接口成功 = 受理成功，`status` 一般为 `PENDING`，不是退款到账。** 到账看 `refund.success` 通知或查退款 `SUCCESS`。

同一 `orderNo` + `businessRefundNo` 再次请求，直接返回已有退款单（可能已是 `SUCCESS` 等终态）。

### 请求示例

```json
{
  "orderNo": "PAY20260911000000001",
  "refundAmount": 50,
  "reason": "用户取消",
  "businessRefundNo": "BRF20260911001"
}
```

### 成功响应

```json
{
  "code": 200,
  "success": true,
  "message": "退款申请已提交",
  "data": {
    "refundNo": "REF20260911000000001",
    "status": "PENDING",
    "refundAmount": 50
  }
}
```

## 9. 查询退款 `GET /api/pay/refunds/{refundNo}`

路径必须是退款单号（`REF` 开头）。传入 `PAY...`：`code=404`，`请使用退款单号（REF 开头）查询，不要使用支付订单号`。

### 成功响应

接口返回退款记录全文。对接使用这些字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| refundNo | string | 支付中心退款单号 |
| orderNo | string | 原支付订单号 |
| businessRefundNo | string \| null | 业务退款单号 |
| refundAmount | number | 本次退款金额，分 |
| totalAmount | number | 原订单金额，分 |
| reason | string | 退款原因 |
| status | string | 见 [退款状态](#113-退款状态) |
| refundedAt | string \| null | 退款完成时间 |
| thirdPartyRefundId | string \| null | 微信退款单号 |
| notifyStatus | string | 业务通知状态 `PENDING` / `SUCCESS` / `FAILED` |
| createdAt | string | 创建时间 |
| updatedAt | string | 更新时间 |

响应里还可能带 `id`、`paymentOrderId`、`rawCallback`、`operator` 等内部字段，对接不要依赖。

```json
{
  "code": 200,
  "success": true,
  "message": "",
  "data": {
    "id": 1,
    "paymentOrderId": 1,
    "orderNo": "PAY20260911000000001",
    "refundNo": "REF20260911000000001",
    "thirdPartyRefundId": null,
    "businessRefundNo": "BRF20260911001",
    "refundAmount": 50,
    "totalAmount": 100,
    "reason": "用户取消",
    "status": "PENDING",
    "refundedAt": null,
    "notifyStatus": "PENDING",
    "createdAt": "2026-09-11T03:20:00.000Z",
    "updatedAt": "2026-09-11T03:20:00.000Z"
  }
}
```

无 `refund.failed` 通知。失败请轮询本接口，直到 `SUCCESS` / `FAILED` / `CLOSED`。

## 10. 异步通知

支付中心在支付成功、退款成功后，向产品配置的 `callbackUrl` 发 **POST**。支付与退款走**同一个 URL**，用 body.`event` 区分。

你们不传通知地址；地址在产品配置里。URL 须公网 HTTPS，10 秒内返回。

### 10.1 请求头

| 头 | 说明 |
|---|---|
| `Content-Type` | `application/json` |
| `X-Notify-Signature` | HMAC-SHA256(原始 body 字符串, `notifyKey`)，**小写 hex** |
| `X-Notify-Timestamp` | Unix **秒**，与 body.`timestamp` 相同 |

### 10.2 验签（必须用原始 body）

```text
signature = HMAC-SHA256(rawBody, notifyKey).digest('hex')   // 小写十六进制
```

**必须用收到的原始字节/字符串验签。** 禁止 `JSON.parse` 后再 `JSON.stringify`：键顺序或空格一变，签名必失败。

Node.js（可直接粘贴）：

```js
const crypto = require('crypto');

/** Express：在 json 解析前保存原始 body */
// app.use(express.json({
//   verify: (req, _res, buf) => { req.rawBody = buf.toString('utf8'); },
// }));

function verifyNotifySignature(rawBody, notifyKey, signatureFromHeader) {
  const expected = crypto.createHmac('sha256', notifyKey).update(rawBody, 'utf8').digest('hex');
  const a = Buffer.from(expected, 'hex');
  const b = Buffer.from(signatureFromHeader || '', 'hex');
  if (a.length !== b.length) return false;
  return crypto.timingSafeEqual(a, b);
}

// 使用：
// const ok = verifyNotifySignature(req.rawBody, process.env.NOTIFY_KEY, req.get('X-Notify-Signature'));
// if (!ok) return res.status(401).send('invalid signature');
```

Python：

```python
import hmac, hashlib

def verify_notify_signature(raw_body: bytes | str, notify_key: str, signature: str) -> bool:
    data = raw_body if isinstance(raw_body, bytes) else raw_body.encode("utf-8")
    expected = hmac.new(notify_key.encode("utf-8"), data, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, (signature or "").lower())
```

建议同时校验 `|now - timestamp|`，例如不超过 5 分钟，防重放。

### 10.3 事件与报文

仅两种事件：**没有** `payment.failed`、**没有** `refund.failed`。

**`payment.success`**

```json
{
  "event": "payment.success",
  "orderNo": "PAY20260911000000001",
  "businessOrderNo": "BIZ20260911001",
  "productCode": "AI_CHAT",
  "amount": 100,
  "status": "SUCCESS",
  "paidAt": "2026-09-11T03:12:00.000Z",
  "attach": "userId=10001",
  "timestamp": 1726032000
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| event | string | 固定 `payment.success` |
| orderNo | string | 支付中心订单号 |
| businessOrderNo | string | 业务订单号 |
| productCode | string | 产品编码 |
| amount | number | 金额，分 |
| status | string | 支付成功时为 `SUCCESS` |
| paidAt | string \| null | ISO8601 |
| attach | string | 下单 `attach`，未传则为 `""` |
| timestamp | number | Unix 秒 |

**`refund.success`**

```json
{
  "event": "refund.success",
  "orderNo": "PAY20260911000000001",
  "businessOrderNo": "BIZ20260911001",
  "productCode": "AI_CHAT",
  "refundNo": "REF20260911000000001",
  "businessRefundNo": "BRF20260911001",
  "refundAmount": 50,
  "totalAmount": 100,
  "refundedAt": "2026-09-11T03:25:00.000Z",
  "timestamp": 1726032900
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| event | string | 固定 `refund.success` |
| refundNo | string | 支付中心退款单号 |
| businessRefundNo | string | 未传则为 `""` |
| refundAmount | number | 本次退款金额，分 |
| totalAmount | number | 原订单金额，分 |
| refundedAt | string \| null | 退款完成时间 |

同一 `orderNo` / `refundNo` 可能重复通知，接收端必须幂等。

### 10.4 应答与重试

支付中心把 **HTTP 200** 视为通知成功；非 200 时若 body 含 `success`（不区分大小写）也视为成功。建议直接：

```http
HTTP/1.1 200 OK
Content-Type: text/plain

success
```

失败会重试，**最多 7 次**，间隔约：1s → 5s → 30s → 3min → 10min → 30min → 60min。验签失败、业务处理失败请返回非 200，以便重试。

## 11. 字段与枚举

### 11.1 金额、货币、渠道、支付方式

| 项 | 取值 |
|---|---|
| 金额 | 整数，单位 **分**。请求里必须是 JSON number，不要传字符串 |
| 货币 | 固定 `CNY`，下单接口不传 |
| channel | 仅 `WECHAT` |
| payType | `JSAPI`、`H5`、`NATIVE`（`APP` 未开放） |

### 11.2 订单状态

| 值 | 含义 |
|---|---|
| CREATED | 已落单，尚未调起渠道 |
| PAYING | 已向微信下单，待支付 |
| SUCCESS | 支付成功 |
| FAILED | 支付失败 |
| CLOSED | 超时或主动关闭 |
| REFUNDING | 存在进行中/部分退款 |
| REFUNDED | 已全额退款 |

### 11.3 退款状态

| 值 | 含义 |
|---|---|
| PENDING | 已受理，尚未（或刚）提交渠道 |
| PROCESSING | 已提交微信，等待结果 |
| SUCCESS | 退款成功 |
| FAILED | 退款失败（不占用可退额度） |
| CLOSED | 退款关闭（不占用可退额度） |

### 11.4 单号规则

| 类型 | 格式 | 示例 |
|---|---|---|
| 支付订单号 | `PAY{YYYYMMDD}{9位序列}` | `PAY20260911000000001` |
| 退款单号 | `REF{YYYYMMDD}{9位序列}` | `REF20260911000000001` |
| 业务订单号 | 你们生成，≤128 | `BIZ20260911001` |
| 业务退款单号 | 你们生成，≤128，可选 | `BRF20260911001` |

## 12. 错误码

除 429 外，HTTP 状态码都是 **200**，看 body.`code`。

| code | HTTP | 含义 |
|---|---|---|
| 200 | 200 | 业务成功 |
| 400 | 200 | 参数错误 / 业务校验失败 |
| 401 | 200 | 缺少或无效 API Key |
| 403 | 200 | 产品已禁用 |
| 404 | 200 | 订单/退款单不存在，或路径不存在 |
| 429 | **429** | 频率超限 |
| 500 | 200 | 服务器内部错误 |

常见 `message`（`code=400/401/403/404`）：

| message | 场景 |
|---|---|
| 缺少 Authorization 头 | 未带 Bearer |
| API Key 无效 | Key 错误 |
| 产品已禁用 | 产品 status=0 |
| 该产品未配置此支付渠道 | 未做渠道映射 |
| JSAPI 支付需要 openid | `payType=JSAPI` 未传 `payerOpenId` |
| 不支持的支付类型 | `payType` 非 JSAPI/H5/NATIVE |
| 业务订单已支付成功，请勿重复下单 | 幂等：已 SUCCESS |
| 订单已关闭，请重新下单 | 幂等：已 CLOSED |
| 订单不存在 | 查单/关单/退款找不到本产品订单 |
| 当前订单状态 [X] 不可关闭 | 非 CREATED/PAYING |
| 订单已全额退款 | 无可退余额 |
| 当前订单状态（X）不允许退款 | 非 SUCCESS/REFUNDING |
| 退款金额超出可退范围，已占用 X 分，最多可再退 Y 分 | 超额退款 |
| 退款单不存在 | 退款单号错误或不属于本产品 |
| 请使用退款单号（REF 开头）查询，不要使用支付订单号 | 查退款传了 PAY 单号 |
| 接口资源不存在 | 路径错误 |
| 请求过于频繁，请稍后再试 | 429 |

## 13. 对接注意

- **幂等键**：下单用同一产品下的 `businessOrderNo`；退款用同一支付单下的 `businessRefundNo`。关单后须换新业务单号。
- **退款接口成功 = `PENDING` 受理**，不是退款完成。完成以 `refund.success` 或查单 `SUCCESS` 为准。
- **没有 `refund.failed` / `payment.failed` 通知**。失败、超时用查单补偿。
- **JSAPI 的 `payerOpenId` 必须与下单 APPID 同源**（服务号与小程序 openid 不能混用）。
- **H5 必须传用户真实公网 `clientIp`**。不传时代码会落到 `127.0.0.1`，微信会拒单。
- **查单只读本地库**，不实时查微信。回调未到时可能仍是 `PAYING`。
- **`amount` / `refundAmount` 必须是 JSON 整数**（分），传字符串会 400。
- **前端调起成功 ≠ 支付成功**。以通知或查单 `SUCCESS` 为准。
- 不要调用 `/api/pay/callback/*`。不要传 `channel=ALIPAY`、`payType=APP`。

## 14. 完整 curl 示例

把 `<BASE>`、`<apiKey>` 换成实际值。本地默认 `<BASE>=http://localhost:38417`。

### 14.1 Native 下单

```bash
curl -sS -X POST '<BASE>/api/pay/orders' \
  -H 'Authorization: Bearer <apiKey>' \
  -H 'Content-Type: application/json' \
  -d '{
    "businessOrderNo": "BIZ20260911003",
    "amount": 1,
    "subject": "联调 0.01 元",
    "channel": "WECHAT",
    "payType": "NATIVE"
  }'
```

### 14.2 JSAPI 下单

```bash
curl -sS -X POST '<BASE>/api/pay/orders' \
  -H 'Authorization: Bearer <apiKey>' \
  -H 'Content-Type: application/json' \
  -d '{
    "businessOrderNo": "BIZ20260911001",
    "amount": 100,
    "subject": "会员充值",
    "channel": "WECHAT",
    "payType": "JSAPI",
    "payerOpenId": "oXXXX",
    "attach": "userId=10001",
    "expireMinutes": 30
  }'
```

### 14.3 H5 下单

```bash
curl -sS -X POST '<BASE>/api/pay/orders' \
  -H 'Authorization: Bearer <apiKey>' \
  -H 'Content-Type: application/json' \
  -d '{
    "businessOrderNo": "BIZ20260911002",
    "amount": 100,
    "subject": "会员充值",
    "channel": "WECHAT",
    "payType": "H5",
    "clientIp": "114.221.90.24"
  }'
```

### 14.4 按支付单号查单

```bash
curl -sS '<BASE>/api/pay/orders/PAY20260911000000001' \
  -H 'Authorization: Bearer <apiKey>'
```

### 14.5 按业务单号查单

```bash
curl -sS '<BASE>/api/pay/orders/business/BIZ20260911003' \
  -H 'Authorization: Bearer <apiKey>'
```

### 14.6 关单

```bash
curl -sS -X POST '<BASE>/api/pay/orders/PAY20260911000000001/close' \
  -H 'Authorization: Bearer <apiKey>'
```

### 14.7 申请退款

```bash
curl -sS -X POST '<BASE>/api/pay/refunds' \
  -H 'Authorization: Bearer <apiKey>' \
  -H 'Content-Type: application/json' \
  -d '{
    "orderNo": "PAY20260911000000001",
    "refundAmount": 1,
    "reason": "用户取消",
    "businessRefundNo": "BRF20260911001"
  }'
```

### 14.8 查退款

```bash
curl -sS '<BASE>/api/pay/refunds/REF20260911000000001' \
  -H 'Authorization: Bearer <apiKey>'
```
