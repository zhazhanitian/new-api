# v2 视频生成接口

> 状态：规范草案，尚未改代码。本文只定对外输入输出，渠道内部怎么转换后面再做。
> 范围：平台当前视频只有两条渠道，火山豆包和腾讯云点播。v1 `POST /v1/video/generations` 保持不变。

## 1. 原则

外层只放两条渠道都有、且含义相同的字段。某个模型才有的能力放进 `metadata`，键名由平台规定，渠道按白名单转换。上游不认识的键由该渠道忽略。

`resolution` 和 `ratio` 分开。不再使用 `size`，也不再把分辨率和宽高比塞进同一个字符串。

素材用 `inputs` 对象数组，用途由 `role` 决定，不看数组第几项。

外层已经有的字段，`metadata` 里同名键不生效。

## 2. 接口

创建和查询返回同一个对象。创建时还没有成片，`video` 为空。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/v2/video/generations` | 创建任务，立即返回排队中的对象 |
| GET | `/v2/video/generations/:id` | 查询同一个对象 |

## 3. 输入

```json
{
  "model": "sora-video-2.0",
  "prompt": "未来城市，高架轨道飞行器穿梭",
  "inputs": [
    { "type": "image", "url": "https://a.jpg", "role": "first_frame" },
    { "type": "image", "url": "https://b.jpg", "role": "reference_image", "reference_type": "subject", "name": "小猫" }
  ],
  "resolution": "720p",
  "ratio": "16:9",
  "duration": 8,
  "audio": false,
  "metadata": {
    "negative_prompt": "模糊",
    "enhance_prompt": "Enabled",
    "return_last_frame": true,
    "task_type": "auto"
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `model` | 是 | 平台模型名。渠道内部再映射成腾讯的 `ModelName` / `ModelVersion`，或火山的模型 ID |
| `prompt` | 否 | 没有素材时必填。火山放进 `content` 里 `type=text` 的一项；腾讯放进 `Prompt` |
| `inputs` | 否 | 素材列表。不传就是文生视频 |
| `resolution` | 否 | 只表示清晰度。不传用该模型的默认档 |
| `ratio` | 否 | 只表示宽高比。不传用该模型的默认比例 |
| `duration` | 否 | 秒，整数。不传用该模型默认时长。`-1` 只留给支持「由模型决定时长」的豆包模型；腾讯收到 `-1` 直接拒绝 |
| `audio` | 否 | 是否生成声音。火山对应 `generate_audio`；腾讯对应 `AudioGeneration` 的 `Enabled` / `Disabled`。不传就用渠道自己的默认值 |
| `metadata` | 否 | 模型特性，见第 5 节 |

`resolution` 取值：`480p`、`720p`、`768p`、`1080p`、`2k`、`4k`。渠道负责大小写，例如可灵要 `720P`，PixVerse 保持小写。

`ratio` 取值：`16:9`、`9:16`、`1:1`、`4:3`、`3:4`、`2:3`、`3:2`、`21:9`、`adaptive`。

## 4. inputs

| 字段               | 说明                                                                                                                                                                                                    |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `type`           | 只有 `image`、`video`、`audio`。火山 `content.type` 的素材类是 `image_url`、`video_url`、`audio_url`；腾讯 `FileInfos.Category` 是 `Image`、`Video`、`Audio`。文本走外层 `prompt`，样片任务 ID 走 `metadata.draft_task_id`，都不进 `type` |
| `url`            | 公网 `https` 地址，或火山人像库素材 `asset://{asset_id}`。豆包渠道原样转发。`asset://` 由用户自己调人像库拿到 `asset_id` 后拼上，审核通过后的 `resolved_url` 也可以直接传。腾讯不认识 `asset://`，渠道不做判断拒绝，等第三方渠道提交报错即可。这一版不做点播 `FileId` 和裸 Base64             |
| `role`           | 见下表                                                                                                                                                                                                   |
| `reference_type` | 可选，描述这一条素材。腾讯 `ReferenceType`：Kling 视频用 `feature` / `base`，Veo 用 `asset` / `style`，PixVerse 用 `subject` / `background`。火山忽略                                                                           |
| `name`           | 可选，描述这一条素材。PixVerse 多主体名字，提示词里用 `@名字` 引用。火山忽略                                                                                                                                                         |

| `role` | 火山 `content.role` | 腾讯 `FileInfos` |
|---|---|---|
| `first_frame` | `first_frame` | `Category=Image`，`Usage=FirstFrame` |
| `last_frame` | `last_frame` | `Category=Image`，`Usage=LastFrame`。不再使用单独的 `LastFrameUrl` |
| `reference_image` | `reference_image` | `Category=Image`，`Usage=Reference` |
| `reference_video` | `reference_video` | `Category=Video`，`Usage=Reference` |
| `reference_audio` | 音频项的 `reference_audio` | `Category=Audio`，`Usage=Reference` |

火山官方规定首帧、首尾帧、全模态参考三种场景不能混在一次请求里。腾讯允许首帧和参考图同时出现。v2 不在入口禁止混用；模型不支持时，由对应渠道返回明确错误。

纯多图参考写成多项 `reference_image`。不再把 `inputs` 的第一项默认当成首帧。

## 5. metadata

特性字段都放这里，包括只在部分豆包模型上存在的 `return_last_frame`、`task_type`。

| 键 | 说明 | 取值 | 适用 |
|---|---|---|---|
| `negative_prompt` | 不希望出现在画面里的内容。火山没有对应字段，传入后忽略 | 字符串 | 腾讯 |
| `enhance_prompt` | 是否让模型先改写提示词再生成，用来提高成片质量 | `Enabled` 开启，`Disabled` 关闭 | 腾讯 |
| `scene_type` | 切换到模型的专项场景，而不是普通文生或图生视频 | Kling：`motion_control` 动作控制，`avatar_i2v` 数字人，`lip_sync` 对口型。Vidu：`template_effect` 特效模板 | Kling、Vidu |
| `enhance_switch` | 是否把成片增强到目标分辨率。请求的分辨率超过模型直出能力时，上游默认会开；模型能直出时，也可以先出低分辨率再增强 | `Enabled` 开启，`Disabled` 关闭 | 腾讯 |
| `frame_interpolate` | 是否开启 Vidu 智能插帧，让画面运动更连贯 | `Enabled` 开启，`Disabled` 关闭 | Vidu |
| `enable_bgm` | 是否从预设音乐库里自动配一段背景音乐 | `Enabled` 添加，`Disabled` 不添加。默认 `Disabled` | 腾讯 |
| `person_generation` | 是否允许生成人物或人脸 | `AllowAdult` 允许生成成人，`Disallowed` 禁止出现人物或人脸 | 腾讯 |
| `return_last_frame` | 是否在成片之外再返回最后一帧图片。为 `true` 时，查询结果才可能带 `last_frame_url`，可当作下一段视频的首帧。腾讯没有单独的尾帧图，忽略 | `true` 或 `false`，默认 `false` | 豆包 |
| `task_type` | 告诉 Seedance 2.5 这次全模态参考属于哪种子任务，便于提交时先校验参数。模型仍会再看提示词，指定类型和实际判定不一致时任务会失败 | `auto` 自动判断，默认值。`reference` 参考素材生成新视频。`edit` 编辑已有视频，必须有参考视频，宽高比只能是 `adaptive`，时长只能是 `-1`。`extend` 延长已有视频，必须有参考视频，宽高比只能是 `adaptive` | Seedance 2.5 |
| `watermark` | 成片右下角是否打上「AI 生成」水印 | `true` 或 `false`，默认 `false` | 豆包 |
| `logo` | 成片是否加图标水印。与豆包的 `watermark` 不是同一个上游字段 | `Enabled` 开启，`Disabled` 关闭 | 腾讯 |
| `draft` | 是否只生成一段低分辨率样片，用来先确认镜头、动作和提示词是否符合预期。开启后分辨率只能是 `480p` | `true` 或 `false`，默认 `false` | Seedance 2.5 |
| `draft_task_id` | 上一次样片任务的 ID。确认样片可用后，用它生成正式视频。样片 ID 从创建时间起 7 天内有效 | 字符串 | Seedance 2.5 |
| `output_format` | 成片容器格式 | `mp4` 通用播放，默认值。`mov` 色彩精度更高，适合后期调色，部分播放器无法直接播放 | Seedance 2.5 |
| `web_search` | 是否允许模型按提示词自行搜索互联网内容，例如商品、天气。能提高时效性，也会增加等待时间 | `true` 或 `false` | Seedance 2.0、Seedance 2.5 |

v1 里这些键不再进入 v2：`resolution`、`last_frame`、`input_usage`、`video_url`、`audio_generation`、`reference_type`、`pixverse_subjects`。它们分别被外层 `resolution`、`inputs`、`audio` 覆盖。`reference_type` 和主体名字留在素材项上，因为它们描述的是某一条素材。

## 6. 输出

```json
{
  "id": "task_xxx",
  "object": "video",
  "model": "kling-video-2.5",
  "status": "succeeded",
  "progress": 100,
  "created_at": 1785895746,
  "updated_at": 1785895816,
  "video": {
    "url": "https://...",
    "duration": 5.042,
    "width": 1280,
    "height": 720,
    "fps": 24,
    "expires_at": 1785982146
  },
  "last_frame_url": "",
  "error": null,
  "usage": {
    "duration": 5,
    "amount": "1.500000"
  }
}
```

`status` 只有：`queued`、`in_progress`、`succeeded`、`failed`、`expired`、`cancelled`。

| 上游状态 | 对外 `status` |
|---|---|
| 火山 `queued` | `queued` |
| 火山 `running` | `in_progress` |
| 火山 `succeeded` | `succeeded` |
| 火山 `failed` | `failed` |
| 火山 `expired` | `expired` |
| 火山 `cancelled` | `cancelled` |
| 腾讯 `PROCESSING` | `in_progress` |
| 腾讯 `FINISH` 且有视频地址 | `succeeded` |
| 腾讯 `FINISH` 且任务失败 | `failed` |

`progress` 固定是 0 到 100 的整数。失败时 `error` 为 `{ "code", "message" }`，成功时为 `null`。`video` 只在成功后出现。上游没有的字段不返回，不能用请求参数回填。`last_frame_url` 只在请求了 `metadata.return_last_frame` 且上游返回了尾帧图时出现。

`video` 各字段的实际来源：

| 字段 | 火山查询结果 | 腾讯查询结果 | 约定 |
|---|---|---|---|
| `url` | `content.video_url`。文档写地址 24 小时内有效，响应里没有过期时间 | `Output.FileInfos[].FileUrl`。临时存储的实测结果里有地址 | 成功时必有 |
| `duration` | `duration`，整数秒，按总帧数除以 24 向下取整，和真实时长可能差将近 1 秒。创建时指定了 `frames` 则不返回这个字段 | `FileInfos[].MetaData.Duration`，带小数，实测如 `5.042`、`4.1` | 有就返回。类型是数字，不写死整数 |
| `width`、`height` | 查询响应没有宽高 | `MetaData.Width`、`MetaData.Height`，实测有 | 腾讯返回，火山不返回 |
| `fps` | `framespersecond`，文档没有按模型限制 | `MetaData.VideoStreamSet[].Fps`，实测有 | 有就返回 |
| `expires_at` | 没有该字段 | `FileInfos[].ExpireTime`，临时存储实测有值，如 `2026-08-12T02:10:16Z`。任务入参里的 `ExpireTime` 常是空时间，不能用 | 腾讯转成 Unix 秒返回，火山不返回 |

`format`、`resolution`、`ratio` 不放进 `video`。腾讯实测 `FileType` 为空，`MetaData.Container` 是 `mov,mp4,m4a,3gp,3g2,mj2`，不能当成格式。火山的 `output_format` 只有 Seedance 2.5 才返回。`resolution` 和 `ratio` 在火山查询里是请求档位的回显，不是按成片像素测出来的；腾讯成片元数据里没有这两项，只在任务入参 `OutputConfig` 里回显请求值，图生时 Kling 还不传宽高比。

`usage.amount` 是结算后的人民币，6 位小数，和现有生图任务的金额口径一致。未结算完不返回。`usage.duration` 优先用上游实际输出时长：腾讯取 `AigcVideoTask.Output.FileInfos` 的媒体时长，火山取查询结果里的 `duration`。

## 7. 不进入 v2 的字段

这些是渠道自己的运行参数，用户不传，也不进 `metadata`：

- 腾讯：`StorageMode`、`MediaName`、`ClassId`、`ExpireTime`、`FileId`、`Base64`、`ExtInfo`、`SubjectInfos`、`InputRegion`、`Procedure`、`SessionId`、`SessionContext`、`TasksPriority`、`OffPeak`、`ObjectId`、`VoiceId`、`KeepOriginalSound`、`Seed`、合规开关。`SubjectInfos`、`ObjectId`、`VoiceId` 依赖上游主体或音色 ID，下游产品拿不到；用图片保持主体一致时，走 `inputs`。`InputRegion` 只影响腾讯从哪里拉取素材地址，不改变成片，由渠道内部处理。
- 火山：`callback_url`、`execution_expires_after`、`priority`、`safety_identifier`、提示词里的 `--ratio` 写法。另外 `service_tier`、`camera_fixed`、`frames`、`seed` 仅 Seedance 1.0 pro / pro fast 支持，2.0 与 2.5 不支持，不进入 v2。相同 `seed` 也只保证结果相近，不保证两次成片一致。`safety_identifier` 由平台自己填，不交给下游。
