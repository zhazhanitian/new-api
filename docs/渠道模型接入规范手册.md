## 1. 核心设计原则

### 1.1 平台无关性（最重要）

new-api 是 **API 聚合平台**，对外暴露的接口和参数必须以**模型语义**为基准，与底层渠道实现完全解耦。

**禁止做的事：**
- ❌ 文档字段描述中出现渠道名称（如"腾讯 VOD 支持"、"火山引擎专属"）
- ❌ 将渠道平台私有字段（如平台内部版本号、平台特有开关）暴露为用户可传参数
- ❌ 按照所对接平台的字段命名来定义对外参数（平台可能二次封装了原厂字段名）
- ❌ 对外参数结构因平台不同而产生分叉（同一模型多渠道接入时参数必须一致）

**应该做的事：**
- ✅ 字段以原厂模型规范（通常为 OpenAI 规范）或行业通用语义为准
- ✅ 平台特有的路由信息（SubAppId、WorkspaceId 等）放入渠道 API Key 配置中
- ✅ 不具备通用性的平台私有功能直接丢弃，不透传也不暴露
- ✅ 跨渠道共用的扩展参数（`negative_prompt`、`seed` 等）统一放入 `extra_fields` 或 `metadata`

### 1.2 单一职责

- 适配器只负责**协议转换**：将平台无关的标准请求翻译为平台私有协议，并将响应翻译回标准格式
- 不在适配器中做业务逻辑、计费、鉴权（这些由框架处理）

### 1.3 两种接入模式

| 模式 | 适用场景 | 对外端点 | 实现接口 |
|------|----------|----------|----------|
| **同步模式** | 响应时间 < 30s，或需 OpenAI 兼容 | `POST /v1/images/generations` | `channel.Adaptor` |
| **异步模式** | 响应时间 > 30s，任务型 API | `POST /v1/image-tasks/submit` + `GET /v1/image-tasks/:id` | `channel.TaskAdaptor` |

同一渠道可以**同时实现两种模式**（同步模式内部轮询，异步模式暴露原生任务接口）。

## 2. 适配器模式说明

### 2.1 同步适配器 `channel.Adaptor`

调用链：

```
客户端 POST /v1/images/generations
  → middleware/distributor.go   (relay_mode 识别)
  → relay/relay_adaptor.go      (GetAdaptor → 选择适配器)
  → Adaptor.Init()              (解析凭证)
  → Adaptor.ConvertImageRequest()  (标准请求 → 平台请求)
  → Adaptor.DoRequest()         (发送 HTTP，含内部轮询)
  → Adaptor.DoResponse()        (平台响应 → OpenAI 格式)
  → 返回客户端
```

### 2.2 异步适配器 `channel.TaskAdaptor`

调用链：

```
客户端 POST /v1/image-tasks/submit
  → TaskAdaptor.Init()
  → TaskAdaptor.BuildRequestBody()   (构造提交请求)
  → TaskAdaptor.BuildRequestHeader() (签名/鉴权头)
  → TaskAdaptor.DoRequest()          (提交任务)
  → TaskAdaptor.DoResponse()         (返回任务 ID)

客户端 GET /v1/image-tasks/:task_id
  → TaskAdaptor.FetchTask()          (轮询平台任务状态)
  → TaskAdaptor.ParseTaskResult()    (解析状态/结果)
  → TaskAdaptor.ConvertToOpenAIVideo() (转换为标准格式)
```

**关键细节（实现前必读）：**

1. **Billing 接口（必须实现三个方法）**
   `channel.TaskAdaptor` 要求实现 `EstimateBilling`、`AdjustBillingOnSubmit`、`AdjustBillingOnComplete`。
   不需要自定义计费的渠道，直接在结构体中嵌入 `taskcommon.BaseBilling`，即可获得三个 no-op 默认实现，无需手动编写：
   ```go
   type TaskAdaptor struct {
       taskcommon.BaseBilling  // 嵌入即提供三个计费方法的默认实现
       apiKey string
       // ...
   }
   ```

2. **OpenAIVideoConverter 接口（视频渠道必须实现）**
   `channel.OpenAIVideoConverter` 定义了 `ConvertToOpenAIVideo(originTask *model.Task) ([]byte, error)`。
   视频渠道的 `TaskAdaptor` 必须实现此方法，否则 `GET /v1/videos/:task_id` 查询接口将返回错误。
   实现位于同一 `task_adaptor.go` 文件，从 `originTask.Data` 反序列化查询响应并组装 `dto.OpenAIVideo`。

## 3. 接入全流程

### Step 1 — 注册渠道类型常量

**文件：`constant/channel.go`**

```go
// 在 iota 列表末尾（ChannelTypeDummy 之前）追加：
ChannelTypeXxx = N   // N 为下一个可用编号（当前最大值+1）

// ChannelBaseURLs 追加（索引对应渠道类型编号）：
"https://api.xxx.com",  // N

// ChannelTypeNames 追加：
ChannelTypeXxx: "XxxPlatform",
```

**文件：`constant/api_type.go`**

```go
// 在 APITypeDummy 之前追加：
APITypeXxx
```

**文件：`common/api_type.go`**

```go
// ChannelType2APIType switch 追加：
case constant.ChannelTypeXxx:
    apiType = constant.APITypeXxx
```

### Step 2 — 创建适配器包

```
relay/channel/task/xxx/
├── sign.go          // 平台签名/鉴权实现
├── constants.go     // ChannelName、ModelList、参数映射表
├── adaptor.go       // 同步适配器（可选）
└── task_adaptor.go  // 异步适配器（可选）
```

**`constants.go` 必须包含：**

```go
package xxx

const ChannelName = "XxxPlatform"

// ModelList 是该渠道支持的模型列表（填写原厂/OpenAI 模型名）
var ModelList = []string{"model-a", "model-b"}
```

**参数映射表写在 `constants.go` 中，禁止硬编码在业务逻辑里：**

```go
// 示例：quality → 平台内部参数的映射
var qualityMap = map[string]string{
    "standard": "xxx_v1",
    "hd":       "xxx_v2",
}
```

### Step 3 — 实现 `Init()` 方法（凭证解析）

API Key 格式约定见[第 5 节](#5-凭证管理规范)。

```go
func (a *Adaptor) Init(info *relaycommon.RelayInfo) {
    a.baseURL = info.ChannelBaseUrl
    parts := strings.Split(info.ApiKey, "|")
    // 按照本渠道约定的字段顺序解析
    if len(parts) == 2 {
        a.appId = strings.TrimSpace(parts[0])
        a.apiKey = strings.TrimSpace(parts[1])
    }
}
```

### Step 4 — 注册适配器

**文件：`relay/relay_adaptor.go`**

```go
import xxx "github.com/QuantumNous/new-api/relay/channel/task/xxx"

// GetAdaptor（同步）
case constant.APITypeXxx:
    return &xxx.Adaptor{}

// GetTaskAdaptor（异步）
case constant.ChannelTypeXxx:
    return &xxx.TaskAdaptor{}
```

> **【纯异步渠道的特殊要求】**
>
> 即便渠道仅支持异步任务（无同步能力），仍然**必须**在 `GetAdaptor` 中注册一个 stub Adaptor，原因如下：
>
> `ChannelType2APIType(channelType)` 返回 `APITypeXxx`（非 -1）后，如果 `GetAdaptor(APITypeXxx)` 返回 `nil`，
> 某些代码路径（如渠道健康检测）调用 `nil.Init(...)` 会导致 nil pointer panic。
>
> 纯异步渠道的同步 stub 只需实现 `channel.Adaptor` 接口，所有方法返回 `"xxx: not supported"` 错误即可（参考 `tencentvod/adaptor.go` 或 `joyagent/adaptor.go`）。

### Step 5 — 路由注册（仅新增端点时需要）

如果复用已有端点（`/v1/images/generations`、`/v1/image-tasks/submit`），跳过此步。

新增端点时修改 `router/video-router.go` 并在 `middleware/distributor.go` 增加 `relay_mode` 识别逻辑。

### Step 6 — 编写 OpenAPI 文档

见[第 6 节](#6-文档规范)。

### Step 7 — 前端 UI 注册

见[第 7 节](#7-前端-ui-注册规范)。

### Step 8 — 编译验证

```bash
# 验证新包
go vet ./relay/channel/task/xxx/...

# 验证核心模块
go build ./constant/... ./common/... ./relay/... ./router/... ./middleware/...
```

## 4. API 参数设计规范

### 4.1 顶层标准参数（直接复用，不重复定义）

这些字段已在框架 `dto.ImageRequest` / `dto.TaskSubmitReq` 中定义，直接使用：

| 字段 | 类型 | 说明 |
|------|------|------|
| `model` | string | 模型名称（必传） |
| `prompt` | string | 正向提示词（必传） |
| `size` | string | 图像尺寸，格式 `宽x高` |
| `quality` | string | 质量：`standard` / `hd` |
| `n` | integer | 生成数量 |

### 4.2 扩展参数约定

**同步接口**（`/v1/images/generations`）：扩展参数通过 `extra_fields` 对象传递。

**异步接口**（`/v1/image-tasks/submit`）：扩展参数通过 `metadata` 对象传递。

**当前已定义的通用扩展字段（不得重复定义）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `negative_prompt` | string | 反向提示词 |
| `seed` | integer | 随机种子 |

**新增扩展字段的判断标准：**

1. **通用性**：该字段是否在多个平台/模型中存在（即使命名不同）？如果是，统一为原厂/OpenAI 名称
2. **语义清晰**：字段含义是否能用一句话说清楚，与底层平台无关？
3. **不具备通用性的功能**：直接丢弃，不透传，不暴露给用户

### 4.3 禁止暴露给用户的字段类型

| 类型 | 举例 | 正确处理方式 |
|------|------|-------------|
| 平台路由 ID | `sub_app_id`、`workspace_id`、`project_id` | 放入 API Key 字段，由管理员配置 |
| 平台内部版本号 | `model_version: "v2.0"` | 映射自 `quality` 等标准字段 |
| 平台私有开关 | `enhance_prompt`、`auto_refine` | 直接丢弃 |
| 平台内部格式 | `output_type: "BASE64_JPEG"` | 适配器内部硬编码或映射 |

## 5. 凭证管理规范

### 5.1 存储位置

所有凭证（API Key、Secret、AppId、SubAppId 等）**必须**存储在渠道管理页的 **API Key 字段**中，通过 `|` 分隔符组合多个值。运行时由适配器 `Init()` 方法动态解析，无需修改代码或重新部署。

### 5.2 格式约定

```
字段1|字段2|字段3
```

- 分隔符统一使用 `|`
- 字段顺序在渠道文档中明确标注
- 解析时使用 `strings.Split(key, "|")` 并做长度校验
- 每个字段 `strings.TrimSpace()` 去除空白

### 5.3 常见格式示例

| 渠道类型 | API Key 格式 |
|---------|-------------|
| 单密钥（如 OpenAI） | `sk-xxxx` |
| 双密钥（如 AppId+Key） | `AppId\|ApiKey` |
| 三字段（如腾讯系） | `SubAppId\|SecretId\|SecretKey` |

### 5.4 安全要求

- 凭证不得以任何形式写入代码（不得 hardcode）
- 凭证不得打印到日志中
- `Init()` 解析失败时应静默降级（不 panic），后续请求返回鉴权错误

## 6. 文档规范

### 6.1 目录结构

OpenAPI JSON 文件放在：

```
new-api-docs-v1/openapi/generated/ai-model/图像（Images）/
├── 原生OpenAI格式/          ← 同步接口文档
└── 异步图像任务/            ← 异步接口文档
```

MDX 文档页面：

```
new-api-docs-v1/content/docs/{zh,en,ja}/api/ai-model/images/
├── 原生OpenAI格式/
└── 异步任务/
```

### 6.2 字段描述要求

**必须：**
- 描述仅说明字段语义，不提及底层渠道名称
- 注明是否必传、默认值、枚举值
- 若字段仅部分模型支持，描述为"部分模型支持"，不指名道姓

**禁止：**
- `"（腾讯 VOD 支持）"` → ❌
- `"（仅 gpt-image-2 渠道）"` → ❌
- `"standard 对应 v2.0"` → ❌（暴露内部版本号）

**正确示例：**
```json
{
  "negative_prompt": {
    "type": "string",
    "description": "反向提示词，描述不希望在图像中出现的元素。部分模型支持。"
  },
  "quality": {
    "type": "string",
    "description": "图像质量。`standard`（标准质量）或 `hd`（高清质量）。默认 `standard`"
  }
}
```

### 6.3 新增扩展字段的流程

1. 确认该字段满足[第 4.2 节](#42-扩展参数约定)的通用性判断标准
2. 在 `extra_fields`（同步）或 `metadata`（异步）的 `properties` 中新增
3. 同步更新中/英/日三语言 MDX 文档中的字段说明（如果文档有多语言版本）
4. 后端适配器中实现对该字段的读取和映射

## 7. 前端 UI 注册规范

每个新渠道类型必须在以下 3 处注册，否则管理员在控制台无法选择该渠道类型：

### 7.1 `web/default/src/features/channels/constants.ts`

```typescript
// CHANNEL_TYPES 追加：
N: 'XxxPlatform',

// TYPE_TO_KEY_PROMPT 追加（API Key 格式说明）：
N: 'Format: Field1|Field2|Field3',
```

### 7.2 `web/default/src/features/channels/lib/channel-utils.ts`

```typescript
// getChannelTypeIcon 映射表追加：
N: 'IconName',  // IconName 为 SimpleIcons slug，复用已有图标或找最接近的
```

常用图标 slug 参考：`OpenAI`、`Google`、`Anthropic`、`Tencent`、`Alibaba`、`Amazon`、`Microsoft`

### 7.3 `web/default/src/features/channels/components/drawers/channel-mutate-drawer.tsx`

在现有 `{currentType === N-1 && ...}` 区块之后新增：

```tsx
{currentType === N && (
  <div className='bg-muted/20 space-y-1 rounded-lg border p-4'>
    <div className='text-sm font-semibold'>
      {t('XxxPlatform API Key Format')}
    </div>
    <div className='text-muted-foreground text-xs'>
      {t('Format: Field1|Field2|Field3')}
      <br />
      {t('Field1: xxx（说明）')}
    </div>
  </div>
)}
```
