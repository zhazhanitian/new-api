# New API 价格配置说明

> 本文档记录平台价格配置相关的常见问题与配置方法，供运营/配置人员参考。

---

## 一、计费方式概览

平台支持三种计费方式，在模型倍率设置页面切换：

| 计费方式 | 适用场景 | 说明 |
|---------|---------|------|
| **按量计费** | 普通对话模型 | 直接填输入/输出价格（$/M tokens），最常用 |
| **按次计费** | 固定收费的模型 | 每次调用收固定费用，适合按图片张数收费等场景 |
| **表达式/阶梯计费** | 价格与请求参数挂钩 | 支持根据 token 数、请求参数、时间等动态计算价格 |

---

## 二、内部积分（Quota）换算

平台内部使用积分（quota）体系，不直接用美元扣费。

**默认换算关系：$1 = 500,000 quota**

在填写表达式时，表达式返回值与实际费用的换算：

```
实际费用 = 表达式返回值 / 1,000,000 × 500,000
         = 表达式返回值 × 0.5 (quota 单位)
         = 表达式返回值 / 1,000,000 (美元)
```

对于普通对话模型，表达式系数就是 $/M tokens，填起来很直观（如 `p * 3` 表示 $3/M 输入 token）。

---

## 三、表达式计费变量说明

| 变量 | 含义 | 说明 |
|-----|------|------|
| `p` | 输入 token 数（文本） | 自动排除已单独计费的子类（图片/音频/缓存） |
| `c` | 输出 token 数（文本） | 自动排除已单独计费的子类 |
| `len` | 输入上下文总长度 | 仅用于阶梯条件判断，不参与价格计算 |
| `cr` | 缓存读取 token 数 | 命中缓存时的读取量 |
| `cc` | 缓存创建 token 数（5分钟） | 首次创建缓存时 |
| `cc1h` | 缓存创建 token 数（1小时） | Claude 专属长效缓存 |
| `img` | 图片输入 token 数 | 发给模型的图片（视觉理解） |
| `img_o` | 图片输出 token 数 | 模型生成的图片 |
| `ai` | 音频输入 token 数 | |
| `ao` | 音频输出 token 数 | |

> **注意**：只有在表达式中使用了某个变量，系统才会将其从 `p`/`c` 中剔除单独计算，避免重复收费。

## 四、各场景配置示例

### 4.1 普通对话模型（按量计费）

直接在「按量计费」标签填写即可，无需写表达式。

**示例：Claude Sonnet 4.5**
- 输入价格：`3` （$3/M tokens）
- 输出价格：`15` （$15/M tokens）
- 缓存读取价格：`0.3`
- 缓存创建价格：`3.75`

---

### 4.2 带音频的多模态模型（表达式计费）

适用于：Gemini 系列（音频与文本输入价格不同）

**示例：gemini-3.1-flash-lite-preview**

| 字段 | 值 | 说明 |
|------|----|------|
| 输入价格 | `0.25` | 文本+图片+视频统一 $0.25/M |
| 输出价格 | `1.5` | $1.5/M |
| 缓存读取价格 | `0.03` | $0.03/M |
| 图片输入价格 | `0` | 与文本同价，留在 p 里一起算 |
| 音频输入价格 | `0.5` | $0.5/M，系统自动从 p 中剔出单独计费 |

等价表达式：`tier("base", p * 0.25 + cr * 0.03 + ai * 0.5 + c * 1.5)`

> 图片与文本输入价格相同时，图片输入价格填 0 即可，图片 token 会自动归入 `p` 按文本价格计算。

---

### 4.3 图像生成模型（按 token 计费）

适用于：gpt-image-2、gpt-image-1 等

这类模型的 usage 结构通常为：
- 输入：文本 token（`p`）
- 输出：图片 token（`img_o`）

**配置：**

| 字段 | 值 |
|------|----|
| 输入价格 | `5` |
| 输出价格 | `10` |
| 图片输入价格 | `8`（如有图生图场景） |
| 图片输出价格 | `32` |

等价表达式：`tier("base", p * 5 + img * 8 + c * 10 + img_o * 32)`

---

### 4.4 图像生成模型（按分辨率/张数计费）

适用于：按图片尺寸收费的模型

**表达式（含多张图支持）：**

```
(param("size") == "4096x4096" ? tier("4K", 18000) : param("size") == "2048x2048" ? tier("2K", 12000) : tier("1K", 6000)) * (param("n") != nil ? param("n") : 1)
```

价格对应关系（基于默认汇率 $1 = 500,000 quota）：

| 档位 | 表达式值 | 对应价格 |
|-----|---------|---------|
| 1K 图 | 6,000 | $0.006/张 |
| 2K 图 | 12,000 | $0.012/张 |
| 4K 图 | 18,000 | $0.018/张 |

> `param("size")` 读取请求 body 中的 `size` 字段，`param("n")` 读取图片数量。
> Token 估算器会提示 "param is not defined"，这是预览工具的限制，不影响实际计费，直接保存即可。

## 五、缓存价格说明（Claude 专属）

Claude 系列模型支持 **Prompt Caching** 功能，分为两种计费：

| 计费项 | 触发时机 | 特点 |
|------|---------|------|
| **缓存创建价格** | 客户端发送带 `cache_control` 标记的请求，首次写入缓存时 | 略贵于普通输入（约 1.25x），需要存储成本 |
| **缓存读取价格** | 后续请求命中已缓存内容时 | 远低于普通输入（约 10%），多次复用越省钱 |

**触发条件**：客户端必须在请求中显式加 `cache_control` 标记才会触发，普通调用不产生缓存费用。

**示例场景**：长系统提示词（如知识库、角色设定）在多轮对话中保持不变时，使用缓存可大幅降低成本。

## 六、模型广场端点配置

在模型管理的「展示端点」字段，可控制模型广场中显示的 API 接口地址（仅影响展示，不影响实际路由）。

| 端点类型 Key | 对应接口 | 适用模型 |
|------------|---------|---------|
| `openai` | `/v1/chat/completions` | 普通对话模型（默认） |
| `openai-response` | `/v1/responses` | gpt-5.4-pro、gpt-5.3-codex 等 |
| `image-generation` | `/v1/images/generations` | gpt-image-2 等图像生成模型 |
| `embeddings` | `/v1/embeddings` | 向量模型 |

**填写格式（JSON）：**

```json
{"openai-response": {"path": "/v1/responses", "method": "POST"}}
```

```json
{"image-generation": {"path": "/v1/images/generations", "method": "POST"}}
```

> 填写后替换默认端点（不合并），若需同时展示多个端点，在同一 JSON 对象中写多个 key。
