# 数据库迁移（国内 → 海外）

> 适用场景：将国内生产服务器的 PostgreSQL 数据库完整迁移到海外服务器。
>
> 服务器路径约定：
> - 国内生产服务器项目目录：`/www/wwwroot/newapi/new-api-main`
> - 海外服务器项目目录：`/www/wwwroot/newapi/new-api-main`（按实际路径调整）

---

## 一、在国内服务器导出数据库

```bash
# SSH 登录国内服务器
ssh root@国内服务器IP

# 进入项目目录
cd /www/wwwroot/newapi/new-api-main

# 在 postgres 容器内执行 pg_dump，导出为自定义压缩格式
docker exec postgres pg_dump -U root -d new-api --no-owner --no-acl -Fc -f /tmp/new-api-backup.dump

# 将备份文件从容器复制到宿主机项目目录（文件名带日期方便区分）
docker cp postgres:/tmp/new-api-backup.dump ./new-api-backup-$(date +%Y%m%d%H%M%S).dump

# 确认文件已生成
ls -lh ./new-api-backup-*.dump
```

## 二、下载备份文件到本机

```bash
# 在本机执行，把文件名改成上一步实际生成的名字
scp root@国内服务器IP:/www/wwwroot/newapi/new-api-main/new-api-backup-XXXXXXXXXXXXXXX.dump ./
```

## 三、上传备份文件到海外服务器

```bash
# 在本机执行
scp ./new-api-backup-XXXXXXXXXXXXXXX.dump root@海外服务器IP:/www/wwwroot/newapi/new-api-main/
```

## 四、在海外服务器导入数据库

```bash
# SSH 登录海外服务器
ssh root@海外服务器IP

# 进入项目目录
cd /www/wwwroot/newapi/new-api-main

# 确认 postgres 容器正在运行
docker ps | grep postgres

# 将备份文件复制进容器（文件名改成实际名字）
docker cp ./new-api-backup-XXXXXXXXXXXXXXX.dump postgres:/tmp/new-api-backup.dump

# 导入数据库（--clean 会先删除旧对象再重建，实现覆盖效果）
docker exec postgres pg_restore -U root -d new-api --no-owner --no-acl --clean --if-exists /tmp/new-api-backup.dump

# 验证导入结果（查询用户表行数）
docker exec postgres psql -U root -d new-api -c "SELECT COUNT(*) FROM users;"
```

> **注意**：`--clean --if-exists` 会覆盖海外数据库中已有的数据，请确认无误后再执行。

---

## 下次迁移快速参考

按顺序执行：**一 → 二 → 三 → 四**
